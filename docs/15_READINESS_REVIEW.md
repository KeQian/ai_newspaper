# 文档完整性与 AI Coding 可执行性审查

> 审查结论：可开始生产级 P0 实现；尚未达到“可直接上线”状态。
> 审查范围：产品、页面、视觉、后端、数据、API、采集、自动化、安全、测试、运维与任务拆解。

## 1. 执行结论

当前文档已经达到 AI coding 工具启动 T01–T14 的标准：范围有优先级、页面有状态、后端有边界、数据有约束、接口可解析、采集有状态机、安全有信任边界、任务有依赖、验收可自动化。

T15 正式上线仍受发布前决策和真实环境验证约束。任何工具都不能把“文档完整”解释为“产品已经通过生产验证”。

## 3. 开发前门禁

- 从 T01 开始，不并行创建另一套架构；
- 生成并提交 lockfile，记录实际依赖版本；
- OpenAPI 与来源 YAML 加入 CI 解析和 lint；
- 创建本地 PostgreSQL、对象存储、邮件捕获和测试身份适配器；
- 用合成数据完成首页、后台登录和单来源采集的最小纵向切片；
- 只有 `enabled: true` 且条款通过的来源可被任务执行。

## 4. 上线前仍需人工确认

这些事项不阻塞 T01–T14，但阻塞生产发布：

1. D-012 部署地区、数据驻留、备案与隐私适用法；
2. D-013 正式品牌、域名、Logo 和联系邮箱；
3. 具体 OIDC、邮件、对象存储和错误追踪供应商；
4. 每个网页/RSS/API 来源的条款、robots、频率和摘录保留策略；
5. 隐私政策、使用条款、Newsletter 同意文案和更正政策的法律审核；
6. 真实告警负责人、值班渠道、预算上限与供应商配额；
7. 14 天数据质量试运行、备份恢复、回滚和安全测试结果。

## 5. AI Coding 交付判定

每次编码任务必须能回答：

- 实现的是追踪矩阵哪一行、backlog 哪个任务？
- 使用了哪个 API Schema、数据库约束和角色权限？
- 正常、空、错误、慢、并发和越权分别如何处理？
- 执行了哪些静态检查、单元/集成/E2E 和视觉检查？
- 是否新增迁移、环境变量、外部依赖或上线风险？

任一问题无明确答案时，任务不能标记完成。
