# 测试策略与验收场景

## 1. 质量门

每个任务必须通过格式检查、静态类型检查、相关单元/集成测试和生产构建。涉及页面时完成 375、768、1440px 浏览器检查；涉及关键链路时运行 E2E。失败时任务不得标记完成。

## 2. P0 E2E

### 内容读取

- Given 存在已发布快讯，When 访问首页和详情，Then 内容、来源、状态和时间一致。
- Given 内容已撤回，When 访问旧 URL，Then 返回可索引控制的撤回说明而非正文或 404。
- Given slug 已更改，When 访问旧 slug，Then 301 到唯一新 URL。
- Given 无封面图，When 在各视口打开，Then 无破图、横向滚动或布局跳动。

### 最新与搜索

- 筛选写入 URL，刷新与前进/后退保持结果。
- 相同时间的游标分页不漏项、不重复。
- 中文、英文、别名、空结果、超长查询均有确定行为。
- 撤回与草稿不能出现在搜索结果。

### Newsletter

- 同一邮箱重复提交始终返回通用 202，不泄露状态。
- 确认 token 一次、重复、过期和篡改均有安全结果。
- 退订立即进入抑制名单；重复退订成功且幂等。
- 未确认、退订、退信和投诉地址不能进入发送批次。

### 后台

- Editor 可以编辑和提交审核，不能发布/撤回/发送。
- ChiefEditor 可以发布但不能管理角色和凭据。
- 并发保存版本冲突时展示 409 和差异，不覆盖。
- 发布失败保留稿件和用户输入；重试不产生重复版本。

### 采集

- 同一外部 ID 重跑不创建重复 raw_document。
- 某来源超时不阻止其他来源完成，run 标记 partial。
- 解析结果异常不推进游标。
- AI 输出不符合 Schema 时不创建正式候选。
- 外部内容包含操作指令时被当作数据，任务不执行该指令。
- GitHub JSON、Hugging Face JSON 与 arXiv Atom 均使用固定 fixture 验证；XML DTD/实体、越界域名、额外查询参数和超过分页上限必须被拒绝。
- 部分失败批次重放时只重试 `failed`/`queued` 来源，已成功来源不得再次发起外部请求。
- 候选输出越界评分、未知字段、缺失或越权 raw document ID 时重试一次；再次失败只进入异常队列，不创建候选。
- 内容哈希完全相同的跨来源记录只创建一个候选；实体与事件相似度只能生成未确认建议，候选保持 review 且公开内容数量不变。

## 3. 单元测试重点

日期/时区、URL 规范化、slug、幂等键、评分边界、状态机、权限矩阵、结构化数据、邮件抑制、HTML 清洗、私网 URL 拒绝。

## 4. 集成测试重点

数据库约束与迁移、发布事务与 outbox、搜索索引更新、来源连接器 fixture、邮件回调签名、管理员会话、审计日志。

## 5. 性能验收

- 公共缓存命中页面 p95 TTFB ≤ 500ms；未命中内容 API p95 ≤ 800ms。
- LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1，在 Lighthouse Mobile、Fast 4G、4x CPU slowdown 下检查。
- 首页首屏业务 JavaScript预算 150KB gzip；超出需记录原因。
- 20 条内容列表查询 p95 ≤ 300ms（预发布基准数据至少 10,000 条 content）。

## 6. 可访问性验收

- axe 无 critical/serious 问题。
- 键盘可完成导航、搜索、订阅和后台审核。
- 200% 字体缩放不丢操作；状态不只靠颜色；Dialog 焦点恢复正确。

## 7. 数据质量验收

- 候选均至少关联一条 raw_document。
- 发布内容均至少一个来源，例外必须有审计理由。
- 14 天核心来源成功率 ≥ 98%，解析 fixture ≥ 99%。
- 抽样 100 条候选：错误实体率 < 3%，错误自动合并为 0。

## 8. 发布阻断

认证、发布、撤回、订阅、退订或采集幂等失败；越权；草稿泄露；提示注入导致越界操作；数据库迁移不可前后兼容；严重无障碍问题；未处理的高危依赖漏洞。
