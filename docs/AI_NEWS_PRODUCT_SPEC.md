# AI 决策情报网站：完整页面级产品需求

> 文档状态：V1.0，产品需求基线
> 产品代号：AI Signal（正式品牌名待定）
> 首发语言：简体中文
> 核心用户：产品经理、创业者、技术管理者、投资与企业创新人员
> 产品承诺：每天 10 分钟，看懂 AI 变化，并知道下一步该做什么。

本产品包含公共网站、编辑后台、数据采集处理管线和 Newsletter 服务，不是纯前端项目。后端边界、数据来源与 Codex 定时任务方案见 [`BACKEND_DATA_FEASIBILITY.md`](./BACKEND_DATA_FEASIBILITY.md)。当前版本不包含会员、付费墙、订单和支付。

## 1. 产品目标与边界

### 1.1 核心用户任务

用户访问网站时需要快速完成：

- 判断今天最重要的 3 件 AI 事件。
- 理解事件对自身岗位、产品或业务的影响。
- 获取原始信息和证据，而不是只看二手摘要。
- 关注公司、产品、模型或主题，并在出现重要变化时收到提醒。
- 将有价值的信息收藏、分享或纳入工作决策。

### 1.2 北极星指标

**每周完成至少一次“有效情报动作”的活跃用户数。**

P0 有效情报动作包括分享、点击一手来源、阅读深度内容达到 70% 或订阅日报。收藏、关注和提醒在 P1 上线后纳入统计。

### 1.3 首版不做

- 原生 App。
- 开放评论区和论坛。
- 用户投稿发布系统。
- 自动生成海量 SEO 页面。
- 实时股票或代币交易信息。
- 复杂社交关系和私信。
- 面向所有行业的通用新闻聚合。

### 3.1 顶部导航

桌面端高度 64px，内容最大宽度 1200px：

- 左侧：Logo，点击返回首页。
- 中部：今日简报、最新、深度、主题、数据库（P1）。
- 右侧：搜索、Newsletter 订阅按钮；P1 上线公开账户后再增加登录头像。
- 页面滚动超过 96px 后吸顶，背景为 95% 不透明，并显示 1px 底部分隔线。
- 当前栏目必须有明确选中态，不只依赖颜色，需同时使用字重或下划线。

移动端：

- 顶栏高度 56px，Logo、搜索、菜单。
- 菜单打开后为全屏抽屉，P0 包含主要导航和 Newsletter 入口；账户入口从 P1 开始显示。
- 禁止把重要导航隐藏在横向滚动条里。

### 3.2 页脚

包含品牌说明、栏目导航、Newsletter 入口、商业合作、方法论、关于、隐私、条款、内容更正联系方式和版权信息。

## 4. 视觉与设计系统

### 4.1 设计气质

关键词：**可信、克制、清晰、敏捷、有人格。**

视觉参考是高质量商业媒体与专业情报产品的结合，但不得直接模仿任何现有品牌。整体应像“编辑精挑细选的行业终端”，而不是科技公司官网。

### 4.2 色彩

使用语义 Token，不在组件中散落十六进制颜色：

| Token | 浅色建议 | 用途 |
|---|---:|---|
| `--background` | `#F7F7F3` | 全局暖白背景 |
| `--surface` | `#FFFFFF` | 内容容器 |
| `--text-primary` | `#171717` | 正文与标题 |
| `--text-secondary` | `#5E625F` | 辅助信息 |
| `--border` | `#DDDCD5` | 结构分隔 |
| `--brand` | `#E84A27` | 品牌红橙、主行动 |
| `--brand-dark` | `#B83117` | Hover/Active |
| `--positive` | `#16845B` | 正向变化 |
| `--warning` | `#B26A00` | 待确认、风险 |
| `--critical` | `#C93636` | 重大风险 |
| `--info` | `#2563A9` | 信息类标签 |

品牌色只用于关键动作、重要排名和少量强调，不允许满屏品牌色。

### 4.3 字体与排版

- 中文正文优先系统字体栈：`Inter, ui-sans-serif, -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`。
- 数字和数据使用支持 tabular numbers 的字体特性。
- 正文桌面端 17px/1.8，移动端 16px/1.75。
- 文章正文最大宽度 720px；任何长文不得铺满 1200px。
- H1 桌面 44～52px、移动 32～36px；避免每页都使用超大 Hero。
- 时间、来源、状态等元信息 12～14px，但对比度需满足 WCAG AA。

### 4.4 间距与布局

- 4px 基础网格，主要间距使用 8/12/16/24/32/48/64/96。
- 页面最大宽度 1200px；长文 720px；窄表单 480px。
- 桌面内容网格 12 列，24px gutter。
- 卡片圆角 8px，表单和按钮 6px。避免大圆角“玩具感”。
- 阴影仅用于浮层；常规卡片依靠背景和边框区分。

### 4.5 动效

- 普通过渡 120～180ms；抽屉最多 240ms。
- 尊重 `prefers-reduced-motion`。
- 不使用进入视口后大面积淡入，不干扰快速浏览。
- 数字变化、收藏和关注可有微反馈，但不可延迟业务操作。

### 4.6 暗色模式

P0 支持跟随系统，允许用户手动切换并记忆设置。暗色模式不使用纯黑背景，图片和图表必须保证可读性。

## 5. 全局内容模型与状态

### 5.1 内容类型

```ts
type ContentType = "news" | "briefing" | "analysis" | "report";
type VerificationStatus = "confirmed" | "developing" | "unverified";
type ImportanceLevel = 1 | 2 | 3 | 4 | 5;

interface ContentItem {
  id: string;
  type: ContentType;
  slug: string;
  title: string;
  dek: string;
  summary: string;
  body: RichTextDocument;
  coverImage?: Media;
  publishedAt: string;
  updatedAt: string;
  authors: Author[];
  topics: Topic[];
  entities: EntityReference[];
  sources: SourceReference[];
  verificationStatus: VerificationStatus;
  importance: ImportanceLevel;
  actionability: ImportanceLevel;
  aiAssistance?: AIDisclosure;
  readingMinutes: number;
  correctionNotes?: CorrectionNote[];
}
```

### 5.2 来源结构

```ts
interface SourceReference {
  id: string;
  title: string;
  publisher: string;
  url: string;
  sourceType: "primary" | "official" | "media" | "social" | "other";
  publishedAt?: string;
  accessedAt: string;
  archivedUrl?: string;
}
```

### 5.3 通用内容状态

- `confirmed`：绿色圆点 + “已确认”。
- `developing`：橙色圆点 + “持续更新”。
- `unverified`：灰色或警示色 + “尚未证实”，正文首屏必须显示解释。
- 更新过的内容同时显示首次发布时间和最近更新时间。
- 内容被撤回时保留 URL，展示撤回原因，不返回空白或直接删除。

## 6. 页面级详细需求

## 6.1 首页 `/` — P0

### 页面目标

让新用户在 10 秒内理解产品价值，让老用户在 3 分钟内发现当天最重要的信息。

### 桌面布局

```text
┌──────────────── 顶部导航 ────────────────┐
│ 日期 / 今日判断 / 日报订阅                │
├───────────────┬───────────────────────────┤
│ 今日头条 2/3  │ 今日最重要事件（主头条）   │
├───────────────┴───────────────────────────┤
│ 今日 AI 雷达：按时间排列的 6～10 条快讯    │
├───────────────────┬───────────────────────┤
│ 深度分析           │ 趋势观察 / 数据变化    │
├───────────────────┴───────────────────────┤
│ Newsletter CTA / 深度内容推荐              │
└──────────────── 页脚 ─────────────────────┘
```

### 模块

1. **日期与编辑判断**
   - 显示当地日期、星期和一句不超过 36 字的“今日判断”。
   - 不使用占据整屏的营销 Hero。

2. **今日必读**
   - 1 条主头条 + 2 条次头条。
   - 主头条包含栏目、标题、摘要、时间、可信状态、影响对象和封面图。
   - 标题桌面最多 2 行，移动端最多 3 行。
   - 内容不足时自然降级为 1～2 条，不显示空卡片。

3. **AI 雷达**
   - 显示最新 6～10 条快讯。
   - 每条显示时间、标题、重要度、来源数量和“为什么重要”一句话。
   - 支持“全部 / 模型 / 产品 / 商业 / 实战”筛选。
   - 筛选条件写入 URL query，便于分享和返回。

4. **深度分析**
   - 展示 3 条编辑精选。
   - 第一条可带横图，其余使用紧凑列表。

5. **趋势观察**
   - P0 为编辑维护的 5 条趋势列表，不伪造实时热度。
   - 每条包含趋势名称、方向、观察窗口和解释。

6. **订阅 CTA**
   - 文案说明订阅频率、用户收益和隐私承诺。
   - 邮箱输入 + 订阅按钮，不要求用户先注册。
   - 成功后在原位置展示确认状态，避免跳转打断阅读。

### 交互与边界

- 当天无新内容时显示最近一次更新，并提示“编辑正在更新今日简报”。
- 本地已完成订阅的用户再次访问时，CTA 显示“已订阅”与退订/偏好入口；P0 不依赖公开账户系统。
- 首页图片必须有固定比例，避免布局偏移。
- 所有列表点击区域不能互相嵌套链接。

### SEO

- 唯一 H1：当日核心标题或品牌价值主张。
- `WebSite`、`Organization`、精选内容的 `ItemList` 结构化数据。
- 首页 description 需稳定，不能每天自动堆砌关键词。

### 埋点

`home_view`、`headline_click`、`radar_filter`、`source_click`、`newsletter_submit`。

### 验收标准

- 375px 宽度无横向滚动。
- 首屏在正常网络下可直接看到今日必读，不被 Cookie 弹窗遮挡。
- 无封面图时版式仍完整。
- 筛选可通过浏览器前进/后退恢复。

## 6.2 最新动态 `/latest` — P0

### 页面目标

提供高密度但不焦虑的时间流，满足频繁回访用户。

### 页面结构

- H1“最新动态”及最近更新时间。
- 顶部筛选：主题、重要度、可信状态、时间范围。
- 快速开关：“只看重要”“只看已确认”。
- 时间线按“今天 / 昨天 / 更早”分组。
- 桌面右侧为今日主题和 Newsletter CTA；移动端移至列表底部。

### 单条快讯

包含时间、状态、标题、120 字内摘要、为什么重要、主题和来源数量。重要度 4～5 的内容有左侧强调线，但不可整卡变红。收藏按钮从 P1 开始显示。

### 加载策略

- 首屏服务端返回 20 条。
- “加载更多”按钮优先于无限滚动，点击后 URL 更新分页游标。
- 返回列表时恢复滚动位置。

### 空状态

筛选无结果时说明是哪项条件导致，并提供“清除筛选”；全站无数据时展示编辑状态，而非错误页面。

## 6.3 日报 `/briefing/[date]` — P0

### 页面目标

形成每日阅读习惯，并成为 Newsletter 的网页归档页。

### 页面结构

- 日期、期数、主编、预计阅读时间。
- 100～180 字“主编开场”。
- 今日三件大事。
- 值得关注的短消息 5～8 条。
- 今日数据或图表 1 个，可为空。
- 明天观察列表。
- 分享、上一期/下一期；收藏从 P1 开始显示。
- 订阅 CTA。

### 每件大事模板

1. 事实摘要。
2. 为什么重要。
3. 对产品、技术、商业分别意味着什么（无价值的维度可省略）。
4. 一手来源。
5. 编辑判断与置信度。

### 日期行为

- `/briefing` 重定向到最新一期。
- 未来日期返回 404。
- 无发布内容的历史日期展示相邻期推荐，不伪造空日报。

## 6.4 快讯详情 `/news/[slug]` — P0

### 页面目标

以最短时间传达事实、影响与出处。

### 首屏顺序

1. 面包屑。
2. 主题与可信状态。
3. H1 标题。
4. 一句话摘要 `dek`。
5. 作者、发布与更新时间、阅读时间。
6. “30 秒看懂”摘要框。

### 正文顺序

- 发生了什么。
- 为什么重要。
- 影响谁。
- 接下来观察什么。
- 来源与证据。
- AI 辅助说明与更正记录（存在时）。

### 右侧栏（桌面）

- 文章目录（仅正文超过 4 个二级标题时）。
- 相关实体。
- 相关实体；收藏与关注从 P1 开始显示。
- Newsletter CTA。

### 分享

支持复制链接、微信分享提示和系统原生分享。复制成功反馈不超过 2 秒，并提供可访问的状态提示。

### SEO

- `NewsArticle` JSON-LD，字段与页面可见内容一致。
- Canonical、Open Graph、Twitter Card。
- `datePublished`、`dateModified`、作者、图片和来源信息完整。

## 6.5 深度分析 `/analysis/[slug]` — P0

### 页面目标

展现不可替代的判断，驱动收藏、分享和持续回访。

### 页面结构

- 文章首屏与快讯详情一致，但允许更强封面视觉。
- “结论先行”：3～5 条核心判断。
- 正文支持标题、引用、表格、图表、图片、提示框和脚注。
- 文末包含“决策建议”“风险与反例”“方法与来源”。
- 相关内容最多 3 条，避免无休止推荐。

### 阅读体验

- 桌面端正文宽度不超过 720px。
- 长文显示阅读进度，但不得遮挡导航。
- 表格在移动端优先改为卡片或允许局部横向滚动，并显示滚动提示。

## 6.6 主题页 `/topics/[slug]` — P0

### 页面目标

成为用户理解某个 AI 主题的持续入口，而非普通标签归档。

### 页面结构

- 主题名称和 100 字以内解释；关注按钮从 P1 开始显示。
- “当前判断”：编辑维护的主题状态摘要。
- 关键事件时间线。
- 最新动态。
- 深度分析。
- 相关公司、产品和模型（P1）。
- 来源与更新时间。

### 状态

- P1 未登录点击关注：保留意图，登录完成后自动关注并提示成功。
- P1 已关注：显示提醒频率设置。
- 主题合并或改名：旧 URL 301 到新主题。

## 6.7 搜索 `/search` — P0

### 页面目标

帮助用户快速找到事件、实体和历史背景。

### 行为

- 全站搜索入口使用快捷键 `/` 或 `Cmd/Ctrl + K` 打开。
- 弹层提供最近搜索、热门主题和即时建议。
- 完整结果页 URL 为 `/search?q=...&type=...&topic=...`。
- 搜索范围：标题、摘要、正文、公司、产品、模型和主题。
- 结果关键词高亮必须避免破坏 HTML 或引发 XSS。

### 结果页

- 显示结果总数、查询词、筛选和排序。
- 默认按相关性，提供按最新排序。
- 结果卡区分内容类型，展示匹配片段。
- 搜索无结果时提供拼写建议、相关主题和返回最新动态。

### 性能

- 输入建议使用 200～300ms debounce。
- 旧请求必须可取消，避免结果倒序覆盖。
- 搜索接口必须限流并记录异常查询，不记录敏感个人输入。

---

## 6.8 Newsletter `/newsletter` — P0

### 页面目标

将访问者转化为可重复触达的订阅用户。

### 页面结构

- 明确价值：发送频率、阅读时长、包含内容。
- 最近 3 期预览。
- 邮箱订阅表单。
- 读者适合/不适合说明。
- 隐私和退订承诺。
- 订阅成功后的双重确认提示（如系统启用 double opt-in）。

### 表单

- 邮箱前后空格自动清理，但不擅自改变大小写内容。
- 支持重复订阅，返回友好提示，不泄露账户状态。
- 提交中按钮不可重复触发。
- 错误消息紧邻字段并支持屏幕阅读器。
- 后端具备 CSRF、防机器人、限流和幂等处理。

## 6.9 身份认证页面 — P1

路由：`/login`、`/register`、`/forgot-password`。

### 要求

- 首选邮箱验证码或 Magic Link；密码登录作为可选方案。
- 登录成功返回用户原本访问页面，阻止开放重定向漏洞。
- 表单宽度 400～480px，页面不需要营销大图。
- 错误信息不能透露某邮箱是否已注册。
- 频繁请求显示冷却倒计时，并由服务端实际限流。
- 用户协议和隐私政策在提交前可访问。

- 按最近收藏排序。

## 6.11 公司档案 `/companies/[slug]` — P1

### 页面目标

### 页面结构

- 公司名、Logo、简介、官网、地区、成立时间、关注按钮。
- 编辑摘要：“为什么值得关注”。
- 关键指标：融资、估值、员工规模等，仅展示有可靠来源的数据。
- 产品列表。
- 关键事件时间线。
- 相关新闻与分析。
- 数据来源与最近核验日期。

### 数据原则

- 未知字段显示“暂无可靠数据”，禁止用 `0` 替代。
- 估值、收入等必须注明日期、币种和来源。
- 公司更名、收购和关闭使用状态字段保留历史。

## 7. 编辑后台需求 — P0

后台不是视觉重点，但必须可安全完成生产工作。

### 7.1 内容工作流

状态：`draft → in_review → scheduled/published → updated/withdrawn`。

权限：

- 作者：创建和编辑自己的草稿。
- 编辑：审核、修改、安排发布。
- 主编：发布、撤回、管理更正与置顶。
- 管理员：用户、权限和系统配置。

### 7.2 内容编辑器

支持标题、摘要、正文、来源、实体、主题、可信状态、重要度、SEO 字段、封面图、AI 使用说明和定时发布。

发布前验证：

- 标题、摘要、作者、主题、至少一个来源必填。
- 未证实内容必须填写风险说明。
- 封面图必须有替代文本和版权信息。
- 修改已发布内容时记录版本差异。

### 7.3 来源管理

- 去重 URL。
- 标记来源级别和访问日期。
- 链接失效检测。
- 支持保存摘要，不抓取或复制整篇受版权保护的原文。

### 7.4 Newsletter

- 从当日内容选取模块组成一期邮件。
- 预览桌面和移动邮件。
- 测试发送、定时发送和取消排程。
- 记录发送、退信、退订和投诉。
- 退订即时生效。

## 8. 全局组件清单

组件必须独立、类型化、可测试，并有 Storybook 或等效组件展示页。

### 导航与布局

`SiteHeader`、`MobileNavigation`、`SiteFooter`、`PageContainer`、`ArticleLayout`、`AdminLayout`；`AccountLayout` 属于 P1，不进入首发组件任务。

### 内容

`LeadStory`、`StoryCard`、`CompactStoryRow`、`NewsTimelineItem`、`BriefingSection`、`ArticleMeta`、`SourceList`、`VerificationBadge`、`ImportanceIndicator`、`TopicChip`、`EntityLink`、`CorrectionNotice`、`AIDisclosure`。

### 用户操作

P0：`ShareMenu`、`NewsletterForm`、`SearchCommand`、`SearchFilters`。P1：`BookmarkButton`、`FollowButton`、`ReminderFrequencySelect`，首发不得实现或显示。

### 基础 UI

`Button`、`IconButton`、`Input`、`Textarea`、`Select`、`Checkbox`、`RadioGroup`、`Dialog`、`Drawer`、`Tooltip`、`Toast`、`Tabs`、`Pagination`、`Skeleton`、`EmptyState`、`ErrorState`。

### 组件状态标准

- Hover、focus-visible、active、disabled、loading、error 必须定义。
- Icon-only 控件必须有 accessible name。
- Toast 不能承载唯一的错误恢复路径。
- Skeleton 尺寸应接近真实内容，避免布局跳动。

## 9. 响应式规范

建议断点：

- Mobile：`< 640px`
- Tablet：`640–1023px`
- Desktop：`1024–1279px`
- Wide：`≥ 1280px`

核心规则：

- 移动端正文和操作顺序按重要性重排，不只是缩小。
- 触控目标至少 44×44px。
- 两栏布局在 1024px 以下转单栏。
- 右侧栏内容移到正文后，不隐藏来源和可信度信息。
- 表格、代码块和图表必须在 320px 宽度仍可用。
- 横屏、浏览器字体放大 200% 时不得丢失功能。

## 10. 核心业务对象

### 10.1 业务实体

P0：`admin_users`、`authors`、`content_items`、`content_versions`、`topics`、`entities`、`sources`、`content_sources`、`newsletter_subscribers`、`newsletter_issues`、`audit_logs`。P1：公开 `users`、`profiles`、`companies`、`products`、`models`、`follows`、`bookmarks`；P0 不创建这些公开账户与互动表。

### 10.2 产品数据规则

- 时间根据用户时区显示，并同时保留事件发生地时间语境。
- Slug 全局或按内容类型唯一，并保留重定向历史。
- 内容撤回后保留历史状态和说明，避免用户访问到无解释的空页面。
- 金额必须同时说明币种、计价单位和数据日期。
- 缺失信息显示“暂无可靠数据”，不得用 `0` 或推测值代替。

## 11. SEO、分发与可发现性

- 每个内容页生成稳定 canonical URL。
- 自动 sitemap，按内容类型拆分；草稿、账户和后台禁止索引。
- RSS：全站、快讯、深度和主要主题。
- `robots.txt` 明确搜索抓取策略；AI 训练抓取策略单独配置。
- 文章使用 `NewsArticle`/`Article`，站点使用 `Organization`/`WebSite`。
- Open Graph 图片使用服务端模板生成，包含标题、栏目、日期和品牌。
- 标题不超过约 60 个英文字符等效长度；description 约 120～160 个英文字符等效长度，以自然表达优先。
- 核心信息必须存在于服务端输出 HTML，不只在客户端请求后出现。

## 12. 可访问性

目标：WCAG 2.2 AA。

- 全站语义化 landmark、标题层级和跳转到正文链接。
- 所有表单有显式 label、错误说明和输入目的。
- 对比度、焦点态、键盘顺序符合标准。
- Dialog 打开后锁定焦点，关闭后回到触发元素。
- 状态不能只依赖颜色表达。
- 图片有有意义的 alt；装饰图片 alt 为空。
- 图表提供文字结论和数据表替代。
- 动态成功/错误消息使用适当 live region。

---

## 13. 性能与可靠性体验要求

以移动端中等设备为验收基准：

- LCP ≤ 2.5s。
- INP ≤ 200ms。
- CLS ≤ 0.1。
- 首页首屏 JavaScript 尽可能控制在 150KB gzip 以内，第三方脚本单独审查。
- 图片提供明确 width/height、响应式尺寸和现代格式。
- 字体优先系统字体，减少外部字体阻塞。
- 页面级错误边界、超时和重试策略完整。
- 关键读取接口设置合理缓存与失效策略，发布后可主动刷新。
- 重要操作失败后保留用户已经填写或选择的内容，并提供明确恢复路径。

---

## 14. 安全、隐私与合规要求

- 收集最少必要个人信息，提供导出和注销渠道。
- 登录、订阅和搜索需防止恶意批量操作。
- 管理员使用更高强度认证；发布、撤回、批量删除等高风险操作保留记录。
- AI 生成或显著改写内容提供显式说明；生成媒体保留所需元数据和标识。
- 引用只摘录必要内容，不镜像受版权保护的完整文章。

## 15. 数据指标与产品实验

### 15.1 公共字段

所有事件包含：`eventName`、`anonymousId/userId`、`sessionId`、`timestamp`、`pageType`、`contentId?`、`referrer`、`utm`、`deviceClass`。禁止把正文、邮箱或敏感信息写入分析事件。

### 15.2 核心漏斗

```text
访问首页
→ 阅读内容
→ 点击来源 / 分享 / 深度阅读
→ 订阅 Newsletter
→ 30 天持续使用
```

### 15.3 实验原则

- 首版不建立复杂实验平台。
- 每次只测试一个核心变量。
- 禁止用虚假倒计时、默认勾选或模糊取消入口提升转化。
- 实验必须定义主要指标、护栏指标和停止条件。

## 16. 页面验收矩阵

### 16.1 设备与场景

- 最新两个主版本的 Chrome、Safari、Firefox、Edge。
- iOS Safari、Android Chrome。
- 视口至少覆盖 320、375、768、1024、1440px。

### 16.2 发布阻断条件

以下任意一项失败不得发布：

- 后台管理员登录或公开订阅关键链路失败。
- 关键页面存在横向滚动、布局跳动或不可操作控件。
- 结构化数据与页面内容不一致。
- 后台普通用户可访问管理能力。
- 出现个人数据、内部错误详情或未授权内容泄露。
- 存在阻止用户阅读或订阅的严重无障碍问题。

## 18. 产品发布顺序

### Phase 1：基础与设计系统

品牌基础、导航结构、视觉规范、内容结构和编辑工作流。

### Phase 2：免费内容闭环

首页、最新、日报、快讯、深度、主题、搜索、SEO、RSS 和内容发布。

### Phase 3：用户增长闭环

Newsletter 增长优化、基础指标、发送与退订体验；登录注册和账户资料属于 P1，不能作为 P0 发布条件。

### Phase 4：数据产品

公司、产品、模型、关注、收藏、变化提醒与企业入口。

每个 Phase 必须单独完成验收，不允许跳过基础能力直接堆页面。

## 19. 页面完成定义

一个页面只有同时满足以下条件才算完成：

- 符合本规格的信息架构和视觉层级。
- 响应式、键盘、屏幕阅读器和暗色模式可用。
- loading、empty、error、success 状态齐全。
- 元数据、canonical 和结构化数据正确。
- 埋点已定义且不包含敏感数据。
- 在目标浏览器完成视觉检查。
- 用户能够完整完成该页面对应的核心任务。

## 20. 最终产品判断标准

上线前由产品负责人逐页回答：

1. 新用户能否在 10 秒内知道网站提供什么独特价值？
2. 用户能否在 3 分钟内找到当天最重要的信息？
3. 每个关键判断是否能追溯到来源？
4. 每个页面是否提供自然且克制的下一步行动？
5. 去掉 Logo 后，这个产品是否仍不像一个普通新闻模板？
6. 深度内容是否提供了新闻摘要之外的独家判断和数据？
7. 网站变慢、无图、无数据或来源失效时，是否仍然可理解、可恢复？

如果任一答案是否定的，页面不能视为生产完成。
